# Triage Skill (Optimized for It's a Plan & Autonomous Pipeline)

Move issues on the project issue tracker through a state machine of triage roles.

Supports both **Interactive Mode** (when invoked by maintainer in chat) and **Autonomous Mode** (when executed by `@triage-bot` on schedule or trigger).

Every comment posted to the issue tracker during triage **must** start with this disclaimer:

```
> *This was generated by AI during triage.*
```

## Reference docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md): how to write durable agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md): how the `.out-of-scope/` knowledge base works

## Roles & States Mapping in It's a Plan

### Category (Issue Type or Labels)
- `bug`: Something is broken (`issueTypeId` for Bug or label `bug`).
- `enhancement`: New feature or improvement (`issueTypeId` for Feature or label `enhancement`).

### State Roles (Labels on It's a Plan)
- `needs-triage`: Freshly created issue, evaluation in progress.
- `needs-info`: Waiting on reporter for more information (automatically surfaces in user's **Inbox**).
- `ready-for-agent`: Fully specified with an Agent Brief, assigned to `@dev-bot` for execution.
- `ready-for-human`: Needs human implementation / approval.
- `wontfix`: Closed as `canceled` status with explanation.

Every triaged issue carries exactly one state label at a time. Always remove previous state labels when applying a new one.

## Autonomous Mode (Scheduled / Unattended Run by `@triage-bot`)

When running autonomously via `itsaplan-runner` or cron schedule:

1. **Find issues needing attention:**
   Call MCP `list_issues` or `search_issues` for:
   - Issues with label `needs-triage` (or without any triage labels in `Todo`/`Backlog`).
   - Issues with label `needs-info` where the reporter has added a new reply.

2. **Evaluate each issue:**
   - Read issue body and existing comments via `get_issue`.
   - Explore local codebase to check:
     (a) **Redundancy**: Is this already implemented?
     (b) **Prior rejection**: Does `.out-of-scope/` mention this?
     (c) **Completeness**: Are reproduction steps, error logs, and expected behavior clear?

3. **Autonomous Decision & State Transition:**
   - **Case A — Insufficient Information:**
     - Call `add_issue_label` with `needs-info` (and `remove_issue_label` for `needs-triage`).
     - Call `add_comment` posting specific, actionable questions (template below).
     - *Result:* Issue automatically appears in the reporter's **Inbox**.
   - **Case B — Fully Specified & Ready for AI:**
     - Call `add_issue_label` with `ready-for-agent` (and `remove_issue_label` for `needs-triage`/`needs-info`).
     - Call `add_comment` posting a structured **Agent Brief** ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
     - Call `update_issue` to set `assigneeUserId` to **`dev-bot`** (or username `dev-bot`).
     - *Result:* `dev-bot` is immediately triggered to begin TDD implementation.
   - **Case C — Needs Human Implementation:**
     - Call `add_issue_label` with `ready-for-human`.
     - Call `add_comment` posting the brief and why human action is required.
   - **Case D — Invalid / Out of Scope / Already Done:**
     - Call `update_issue` setting status/column to `canceled` (or `Done` if already done) with an explanatory comment.

## Interactive Mode (Invoked by User in Chat)

The maintainer invokes `/triage` and describes what they want in natural language.
Examples:
- *"Show me anything that needs my attention"*
- *"Let's look at TP-42"*
- *"Move TP-42 to ready-for-agent and assign to dev-bot"*

### Workflow:
1. Present the pending issues bucketed into `needs-triage` and `needs-info` with replies.
2. Present recommendation with category, state, and codebase analysis.
3. On user approval, apply MCP tool updates (`add_issue_label`, `update_issue`, `add_comment`).

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**
- [Summary of understood context]

**What we still need from you (@reporter):**
- [Specific actionable question 1]
- [Specific actionable question 2]
```
