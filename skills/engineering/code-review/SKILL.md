# Code Review (It's a Plan Native)

Two-axis review of code changes:
- **Standards**: Does the code conform to repo standards, KISS/YAGNI principles, and Fowler smell heuristics?
- **Spec**: Does the code faithfully implement the originating It's a Plan issue acceptance criteria?

## Autonomous Execution via `@review-bot`

When `@review-bot` is triggered on an It's a Plan issue:

1. **Fetch Issue & Acceptance Criteria:**
   - Call MCP `get_issue` to retrieve the title, description, and Agent Brief.
   - Note the expected behavior and acceptance criteria checklist.

2. **Inspect Code Diff & Test Results:**
   - Identify the changes in git: `git diff main...HEAD` (or recent commit range).
   - Run tests (`bun run test` / `npm test`) and typechecker (`bun run typecheck`) to verify green status.

3. **Two-Axis Analysis:**
   - **Standards Axis:** Check for code duplication, premature abstractions, proper naming, KISS/YAGNI, and security vulnerabilities.
   - **Spec Axis:** Check if every acceptance criterion in the issue has a corresponding passing test.

4. **Post Findings & Handover:**
   - Call MCP `add_comment` posting the structured review verdict:
     ```markdown
     > *This code review was generated by @review-bot.*

     ### Review Summary: [APPROVED / CHANGES REQUESTED]
     
     #### 1. Standards & Quality
     - [Clear, specific feedback or clean approval]

     #### 2. Spec & Acceptance Criteria
     - [x] All criteria verified with passing tests.

     #### Recommendation:
     - [Next action: ready to merge / points to improve]
     ```
   - If **Approved**: Call MCP `update_issue` to set status to `Done` (or assign to human maintainer for merge approval).
   - If **Changes Requested**: Call MCP `update_issue` to set `assigneeUserId` back to `dev-bot` with specific action items.
